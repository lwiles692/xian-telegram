# 功法法宝菜单收拢设计

## 目标

收拢 `/skills` 法宝分类页中过度平铺的操作按钮，让法宝列表只承担状态浏览和快速换装，强化、重铸、分解及本命法宝养成集中到单件法宝操作页。

本次只调整处理器展示与导航，不修改装备、强化、重铸、分解、本命法宝的资格、消耗、收益或数据库结构。

## 法宝列表

法宝列表继续展示器魂数量，以及每件法宝的编号、强化等级、名称、装备或本命状态和完整属性。

每件未被拍卖托管、且有装备槽位的法宝固定占一行按钮：

- 未装备：`装备 #编号`、`操作 #编号`。
- 已装备：`卸下 #编号`、`操作 #编号`。

“装备”和“卸下”占用同一按钮位置，根据当前状态切换文字与行为。列表页不再直接显示强化、重铸、分解、认主、喂养或斩缚按钮。

拍卖托管中的法宝保留“拍卖托管”状态文字，不提供装备、卸下或操作入口，沿用当前不可操作规则。

## 单件法宝操作页

点击 `操作 #编号` 进入只读导航 `skills:item:<instance_id>`。页面重新从服务层读取该玩家名下的法宝，展示：

- 编号、强化等级和名称；
- 已装备、未装备、本命、已斩缚绑定或拍卖托管状态；
- 完整属性；
- 当前器魂数量。

页面根据最新状态生成操作按钮：

- 常规法宝显示强化、重铸；
- 未装备法宝显示分解，已装备法宝不显示分解；
- 没有当前本命法宝、品阶符合且未绑定时显示认主；
- 当前本命法宝未满级时显示喂养，并始终显示斩缚；
- 已斩缚绑定法宝不再显示认主；
- 拍卖托管或已不存在的法宝不提供状态变更按钮。

操作页不重复提供装备或卸下，避免同一职责出现在两个层级。底部提供 `↩️ 返回法宝列表`。

## 回调与导航

进入单件操作页和返回法宝列表属于只读导航，使用普通回调数据。装备、卸下、强化、重铸、分解及本命操作继续通过 `action_callback_data()` 生成一次性令牌，并由现有消费逻辑校验用户、有效期和重复点击。

装备或卸下的结果页返回法宝列表。强化、重铸、认主、喂养或斩缚的结果页提供返回当前法宝操作页的入口，方便连续养成；同时提供返回法宝列表的入口。分解成功后实例已不存在，结果页只返回法宝列表。

若打开他人法宝、已删除法宝或失效编号，页面显示中文提示并只提供返回法宝列表。状态变化以重新读取的结果为准，不依赖上一页快照。

## 代码边界

改动集中在 `handlers/skills.py`：

- 收拢 `render_skills_category()` 的法宝列表按钮；
- 新增单件法宝操作页渲染函数及只读回调；
- 调整操作结果页的上下文返回链接。

业务服务和数据库访问方式保持不变。处理器继续通过 `services.character`、`services.equipment` 与 `services.natal` 完成读取和状态变更，不直接查询数据库。

## 测试

处理器回归测试覆盖：

- 每件普通法宝在列表页仅有装备或卸下按钮，以及一个操作按钮；
- 列表页不再出现强化、重铸、分解及本命按钮；
- 单件操作页按装备、本命、绑定和品阶状态显示正确按钮；
- 所有状态变更按钮仍使用一次性令牌；
- 操作结果返回当前法宝或法宝列表，分解成功后不返回已删除实例；
- 无权访问、实例不存在及拍卖托管状态有稳定的中文回退页面。

实现完成后使用仓库 `.venv` 运行完整 `python -m pytest`，不只运行相关测试文件。
