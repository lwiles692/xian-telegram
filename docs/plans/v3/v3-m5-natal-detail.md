# V3-M5 本命法宝实施细案

> 对应 `v3-m5-natal-outline.md`，作为 M5 动工前的 detail 文件。
> 目标：在不新增周常压力、不绕过交易隔离、不突破全局 clamp 的前提下，落地“认主 / 解缚 / 喂养成长 / 器修协同”。

## 一、实施边界

| 项目 | 定稿口径 |
|---|---|
| 功能定位 | 与境界正交的长期材料 sink；只强化已拥有的法宝实例，不新增战斗新流程 |
| 上线对象 | 元婴期起可用；只允许品阶为 `宝`、`玄` 的法宝实例认主 |
| 红线 | 不提供额外出战次数、不新增周必做、不开放交易套利、不旁路 `ATTACK_PCT_CAP` / `SURVIVAL_PCT_CAP` |
| UI 入口 | 并入 `/skills` 的法宝页，避免再开独立顶层入口 |
| 播报 | 认主、斩缚可进 `game_events`；喂养不群播，避免刷屏 |

## 二、数据结构

| 表 / 字段 | 类型 | 默认 | 说明 |
|---|---:|---:|---|
| `characters.natal_instance_id` | `INTEGER` | `NULL` | 当前本命法宝实例；同一角色同一时刻最多一件 |
| `item_instances.natal_level` | `INTEGER NOT NULL` | `0` | 本命等级，非本命必须为 0 |
| `item_instances.bound` | `INTEGER NOT NULL` | `0` | 实例绑定标记；旧实例回填 0，认主时置 1 |
| `natal_feed_logs` | 新表 | 无 | 记录喂养流水，按 `(user_id, instance_id, level)` 幂等 |

`item_instances.bound` 是 M5 对 M2 拍卖托管语义的显式补强。已有 `status='auction'` 继续表示托管中，`bound=1` 表示永不可进入拍卖路径。

## 三、准入与操作规则

| 操作 | 前置条件 | 消耗 | 结果 |
|---|---|---|---|
| 认主 | 元婴期起；实例归属本人；`tier in {'宝','玄'}`；`status='normal'`；未装备可认主；角色当前无本命 | 见“四、费用曲线” | `characters.natal_instance_id=实例ID`，实例 `bound=1`，`natal_level=1` |
| 喂养 | 已认主；实例仍归属本人；未达 10 级 | 对应下一等级消耗 | 等级 +1，写 `natal_feed_logs` |
| 斩缚 | 已认主；灵石足额 | 高额灵石 | 清空 `natal_instance_id`，实例 `natal_level=0`，保持 `bound=1` |

斩缚不解除绑定，旧器也不可再次认主。理由：本命仪式已消除交易流动性，斩缚只是给玩家换本命的高成本出口，不能变成“养成后再流入市场”或“同一实例反复开新轮次”的套利口。

## 五、属性与 clamp 口径

本命不直接放大平加属性，而是把本命等级折算为百分比加成，进入 `services.character.stats()` 现有 `pct_bonus` 管线，再由 `config/buffs.py` 的 clamp 统一截断。

| 法宝槽位 | 每级加成 | 10 级满额 | clamp 分区 |
|---|---:|---:|---|
| 武器 | `atk_pct +0.006` | `atk_pct +0.06` | ATTACK |
| 护甲 | `hp_pct +0.004`、`df_pct +0.004` | 各 +0.04 | SURVIVAL |
| 饰品 | `mp_pct +0.004`、`spd_pct +0.004` | 各 +0.04 | SURVIVAL |

该口径保证本命是“锦上添花”而不是门槛乘区；与心法、丹药、宗门福利同池累计，超出部分由既有 clamp 吃掉。

## 六、器修协同

| 道途 | 协同 |
|---|---|
| 器修 | 喂养灵石成本 -10%，器魂消耗 -1（最低 1），材料数量不减 |
| 非器修 | 使用标准费用 |

只减消耗，不提高属性上限。器修因此获得长期材料 sink 的手感优势，但不会突破战斗上限。

## 七、交易隔离

| 路径 | 拒绝条件 | 预期状态 |
|---|---|---|
| 拍卖实例上架 | `bound=1` 或 `characters.natal_instance_id=instance_id` | `locked` / `bound` |
| 装备分解 | `bound=1` 且仍为当前本命；或 `natal_level>0` | `natal_bound` |
| 坊市堆叠物 | 不涉及实例 | 不新增入口 |
| 道侣互赠 | 白名单为堆叠物，不含实例 | 不受影响 |

拍卖结算、撤单、出价不改语义；M5 只在上架入口和实例操作入口加显式校验。

## 八、测试与验收矩阵

| 验收项 | 测试建议 |
|---|---|
| schema 幂等 | `tests/test_natal.py::test_schema_本命字段幂等回填` |
| 认主准入 | 元婴门槛、品阶门槛、拍卖托管拒绝、已有本命拒绝 |
| 认主结果 | 扣材料 / 灵石、实例绑定、等级置 1、角色指针写入、事件播报 |
| 喂养成长 | 逐级成本、器修降耗、满级拒绝、幂等日志 |
| 属性 clamp | 本命百分比进入 `ATTACK/SURVIVAL` clamp，满 buff 不突破 25% |
| 交易隔离 | 本命实例不可上拍、不可分解；斩缚后仍不可上拍 |
| 斩缚 | 按等级扣费、清零等级、清空角色指针、绑定保留 |
| 完整动线 | 认主 → 喂养 → 属性提高 → 上拍被拒 → 斩缚 → 重新认主 |
| 平衡 | `python -m tools.balance_sim` 反套利与炼虚材料 sink 输出正常 |

## 九、实施顺序

1. 新增 `config/natal.py`，落常量、费用函数、槽位加成函数。
2. 扩展 `models/db.py` schema 与 `_ensure_column`。
3. 新增 `services/natal.py`，实现认主、喂养、斩缚、概览。
4. 调整 `services.character.stats()` 与实例读取入口，把本命加成纳入 `pct_bonus`。
5. 调整拍卖 / 分解入口，补交易隔离。
6. 在 `handlers/skills.py` 加本命按钮与结果文案。
7. 补 `docs/USER_GUIDE.md` 与 M5 周事件总量审计。
8. 跑 `python -m pytest` 与 `python -m tools.balance_sim`，提交。
