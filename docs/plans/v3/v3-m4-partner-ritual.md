# V3-M4 道侣 + 同步共修仪式

> 对应 spec-v3 §5、§8.2、§10。
> 目标:结契/解除、双修重叠折算、互赠、周双人任务、同步共修仪式(覆盖师徒/道侣两种关系)。
> 前置:M3(`social_bonds` 表与 partner 唯一索引已建,`bonds` 模块已存在)。
> **不做范围(红线)**:任何战斗面攻防加成、同图历练加成、PvP 加成——战斗引擎近二值,
> 道侣不能成为翻门槛的隐形乘区。

---

## 任务清单

### T4.1 同心结与结契 / 解除(`config/bonds.py` + `services/bonds.py`)

- 物品 `同心结`:炼器可制(`config/recipes.py`)/ 周活动商店兑换,**绑定**。
- 结契:双方金丹期+;一人一侣;消耗 1 枚同心结;双向确认(一次性 token + 事务)。
- **镜像双行**:partner 关系 a→b 与 b→a 同事务成对写入/变更(spec §8.2 ②),
  `idx_bonds_partner_a` 单列部分唯一索引精确表达"一人一侣"(M3 已建)。
- 解除:任一方单方解除,消耗灵石 50000(可调);双方 7 天冷却;镜像双行同事务置 `dissolved`。
- 结契/解除入 `game_events` 群播报(解除低调文案)。

**验收**:镜像双行成对一致(单测断言两行状态同步);一人一侣被唯一索引拒(含"一次当 a
一次当 b"交叉场景);解除费用与冷却生效。

### T4.2 双修重叠折算(`models/db.py` + `services/settle.py` + `services/character.py`)

核心机制,spec §5.2 逐条落地:

- `characters += last_seclusion_start INTEGER / last_seclusion_end INTEGER`(`_ensure_column`);
  **每次收功把刚结算的闭关区间写回**(只留最近一段,README §0.B-2:现库只有 `seclusion_at`
  开始时间,无历史区间)。
- 交集算法(落 `services/settle.py` 纯函数,便于单测):结算本方 `[start_at, now]`
  (**先按 `OFFLINE_CAP_HOURS` 截断**)→ 查道侣闭关区段(进行中取 `[partner_seclusion_at, now]`,
  已结束取 `last_seclusion_start/end`)→ 求交集秒数 → 该秒数部分额外 +5%。
  双方各自独立结算,互不触发对方收功。
- **两条收功路径统一生效**:主动出关收功(`collect_seclusion`)与"返回面板自动收功"
  (`touch_activity`)都走同一 helper——v2 审查 B-2 的教训(漏一条路径即结算不一致)。
- **重叠只看闭关区间不看在线状态**:离线自动闭关时段同样计入。
- +5% 计入 SECLUSION clamp;截断透明化文案与 M3 传承共用。
- 收功文案展示:`与道侣同参 137 分钟,双修额外修为 +xxx`;无重叠不展示该行。

**验收**(spec §9):重叠折算含双方离线区间(先截断后求交的边界单测);两条收功路径结果一致;
`last_seclusion_start/end` 收功正确写回且被对方交集查询使用;进 clamp 回归 `test_buff_caps.py`;
文案含同参时长与额外修为。

### T4.3 每日互赠(`config/bonds.py` + `services/bonds.py`)

- 每日一次,向道侣赠 1 件白名单物品(绑定丹药/材料,白名单固定在 `config/bonds.py`)。
- 赠出后仍为绑定;白名单外物品被拒;不可反向套现。

### T4.4 周活动双人任务(`config/weekly_events.py` 管线)

- **同一周内双方各自完成指定活动即算达成**(异步,不要求实时协作),得少量道行。
- 道行计入活动周上限(`WEEKLY_DAOHANG_CAP`),不新增上限额度。

### T4.5 专属展示

- 专属称号 + 面板(`handlers/me.py`)展示道侣;合击 Boss 时专属播报文案。无数值。

### T4.6 同步共修仪式(道侣 + 师徒通用,spec §5.3)

主动协作玩点,限周:

- 数据落点:小表 `communion_sessions(id, kind, a_id, b_id, status, start_at, end_at)` +
  每人限周判定按 `(user_id, ISO 周)` 记录(可并入 `weekly_activity` 加列或独立小表,
  实施时定,原则:重启不丢、每人每周 1 次**跨关系去重**)。
- 流程:一方发起邀请(一次性 token)→ 对方 **10 分钟内确认**即同步开始 → 共修 30 分钟。
- 前置:双方均有 active 的道侣/师徒关系;均不在重伤/其他前台活动中;
  共修**计 `activity_windows`**(仿 `services/activity.record_window`,
  勿用 `reserve_stamina_for_action`——它拒绝闭关中行动)。
- 收益:结束各得一次性修为包 ≈ 各自境界 2~3 小时闭关收益;师徒场合徒弟得修为、师父得少量道行。
- **独立限周奖励,不进 SECLUSION clamp**;错过不补,非每日必做。
- 边界处理(实施时写死并测试):邀请 10 分钟超时作废;共修中一方进入其他前台活动 →
  仪式中断的处理规则确定(建议:中断则双方无收益、本周次数不退,文案明示)。

**验收**(spec §9):每人每周 1 次跨关系去重(与道侣共修过则本周不能再与徒弟共修);
邀请超时作废;中断规则确定并有测试;奖励独立限周包不进 clamp。

## 风险与回避

| 风险 | 回避 |
|---|---|
| 频繁解除/重结契刷双人任务 | 解除费 50000 + 7 天冷却;周任务按周去重 |
| 互赠成灵石/材料搬运通道 | 白名单固定 + 绑定传递 + 白名单外拒绝单测 |
| 双修只改一条收功路径导致两口径不一致 | 共享 helper + "两路径结果一致"专项测试(v2 B-2 教训) |
| 交集查询把 OFFLINE_CAP 截断放在求交之后(多算收益) | 纯函数单测显式覆盖"先截断后求交"边界 |
| 共修中断语义含糊引发客诉 | 中断规则在实施时一次定死 + 文案明示 + 测试固定 |
